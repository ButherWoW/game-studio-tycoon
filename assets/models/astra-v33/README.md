# SpawnPad — площадка появления игрока

Низкая квадратная площадка в центре парка: тёмно-синий постамент с бирюзовой Neon-рамкой и собственным пиксельным картриджем из цветных деталей. Текстур, декалей, надписей и чужих логотипов нет. На верхней плоскости нет выступающих кнопок или украшений.

Финальные `models/SpawnPad.rbxmx` и `models/SpawnPad.rbxm` содержат одну и ту же модель: 37 native Parts, размер **8×0.32×8 studs**. `PrimaryPart = Base`, pivot — центр основания `(0,0,0)`, низY0, верхY0.32. Весь верх8×8 ровный и непрерывный; центральные6×6 полностью свободны. С площадки удобно сходить: ступенька0.32stud. По центру парка16×16 не добавляется вертикальных преград.

Все детали закреплены, `CanCollide=true` для физической опоры. Не применять к площадке общее отключение коллизий декоративных моделей, если вокруг нет другой поверхности на том же уровне. Neon-рамка не содержит PointLight: источников света и теней от них нет. Скриптов, внешних mesh/texture и SpawnLocation внутри шаблона нет.

## Проверка

`VALIDATION.json` — независимый разбор фактического экспортированного XML:666пар, ноль положительных объёмных пересечений. Верхние прямоугольники имеют суммарную площадь64stud², покрытие каждой из90подобластей ровно1, без дыр и двойных участков в допуске0.00001stud. Все верхние поверхности лежат на одномY0.32; низ, габарит, pivot, PrimaryPart, классы и свойства опоры проверены. Хеши обоих форматов сохранены.

`previews/SpawnPad_ContactSheet.png` показывает реальную геометрию сверху и в три четверти. Рендер не является скриншотом Studio; настоящее свечение Neon смотреть в игре.

Исходники в `source/`: build_spawnpad.py создаёт XML/RBXM черезRojo, independent_audit.py проверяет XML без импорта генератора, render_pack.py делает превью. Требуются Python3, Pillow/NumPy; Rojo только для бинарного формата. Никакой генерации растровой картинки для модели не использовалось.
