# Исправление прозрачных панелей гаража — четыре отделки

По замечанию владельца v71 (#26,06.11): в Classic/Aurora/Sakura/ObsidianGold все12панелей WindowGlass/DoorWindow теперь непрозрачны: Transparency=0, SmoothPlastic вместо Glass. Форма, расположение, размер, палитра, pivot и коллизии сохранены. Пиксельных текстур, скриптов и внешних mesh нет.

В каждой оболочке оставлен один PointLight без теней (Range60/Brightness1) вместо четырёх, по правилу ТЗ. Светильники как геометрия сохранены; реальную яркость проверить в Studio.

## Важно: три разных причины, не обещание полного runtime-фикса

1. **Модели:** альфа12оконных панелей была .62/.15. Исправлена здесь для всех4оболочек. Остальные видимые стеновые детали исходно непрозрачны.
2. **Двойная оболочка:** PlotService.buildPlot исключает Garage через supersededOnPlot, но покупка walls вызывает только placeUpgrade и оставляет старый Garage. В source/proposed-remove-superseded-garage.patch — проект исправления для Dev2 (не применён к src): после установки импортированной GarageWalls убрать Garage; Generated-декор не заменяет стены. Это устраняет две оболочки при покупке без relog.
3. **Камера:** StudioCamera.fadeFor:98–120/Config.Camera.fadeTransparency=.85 делает высокие и передние части полупрозрачными через LocalTransparencyModifier. Одной смены RBXM недостаточно. Dev2 должен исключить стены текущего этажа из fading согласно просьбе владельца; скрытие верхних этажей/крыши проверять отдельно.

Геометрия не менялась: новых геометрических пересечений нет. Старые внутренние декоративные стыки принятых моделей не перестраивались; отсутствие всех старых пересечений или мерцания в Studio здесь не заявляется. Замечание о наложении двух Garage исправляется кодом Dev2, а не переносом моделей.

## NPC: передать Dev2

Квадрат над головой — вероятный Head.LifeBubble из StaffLife:86–103, белый TextLabel BackgroundTransparency=.1, размер2×2. Проверенные34Handle аксессуаров прозрачны. Точный объект должен выбрать Dev1 в Explorer: без runtime нельзя доказать, что это именно LifeBubble.

Стояние в гараже: StaffService.chairSeatTop:1113–1146 ищет seat внутри модели стола, исключая PcSeat. В Desk1 есть только PcSeat, Desk2 не содержит сидушки; Chair — отдельная модель. Поэтому код использует standing fallback. Нужен явный NPC-chair/anchor контракт без занятия игрокового PcSeat. В OfficeDesk/FloorDesk/SkyDesk декоративные BlueSeat/SeatCushion присутствуют, для них код уже умеет позу сидя; проверить фактически импортированные модели и matching позиции. Эти задачи — Dev2; модели NPC/кресел здесь не переделываются без подтверждённого дефекта конкретного файла.

## Как проверить в Studio (Dev1)

- Чистый профиль: купить гараж, затем walls. После кодового фикса на участке должна быть одна GarageWalls, без Garage. Проверить сразу и после rejoin.
- Повторить с Classic/Aurora/Sakura/ObsidianGold; переключить мебель Neon/Cozy/Minimal и обратно: оболочка не меняет pivot/позицию.
- Посмотреть снаружи/изнутри и за ПК с авто-видом: панели непрозрачны, LocalTransparencyModifier не делает стены прозрачными после фикса камеры. Нет мерцания двух оболочек.
- Проверить Generated fallback без импортированных шаблонов: базовый Garage остаётся, декор не убирает стены.
- Проверить свет ночью, вход/проходы, рабочие места и ПК. В офисе/этажах проверить скрытие верхних этажей камерой.
- Выбрать квадрат над NPC и записать ClassName/полный путь. Проверить посадку сотрудников за всеми столами во всех4отделках и платных стилях.
