# V29 — BuilderNPC, одежда и BuilderHat

Нативный блочный R15 BuilderNPC: Humanoid(RigType=R15), HumanoidRootPart,15обычных частей тела,15Motor6D и три оригинальные детали лица, приваренные к голове. Итого19BaseParts, с отдельной каской22. Стандартные имена RightShoulder/LeftShoulder/RightElbow/RightHip/LeftHip совпадают с ConstructionController. Никаких внутренних Script/LocalScript, анимаций, mesh/Decal и внешних текстур в геометрии. Молоток и доска не вложены: их добавляет ConstructionService.

Одежда builder_shirt.png/builder_pants.png585×559RGBA: оранжевый жилет с светлыми отражающими полосами поверх синей футболки, тёмно-синие рабочие штаны, ботинки.18UV-панелей из принятой развёртки классической одежды; всё вне панелей прозрачно. Свои SVG, без нейросетевого угадывания UV.

BuilderHat — корневой Accessory из3деталей: жёлтые круглый козырёк-Handle, блочная тулья и верхний гребень, HatAttachment,2жёстких WeldConstraint. Всё unanchored/Massless/noncolliding. Низ каски касается верхней грани канонической головы; геометрия не входит в неё. Форматы RBXMX/RBXM: импортировать только один каждого объекта.

## Важно при установке

1. Dev1 загружает два PNG как Classic Shirt/Pants. В BuilderNPC уже есть экземпляры Shirt/Pants с пустыми Template, потому что ID до загрузки неизвестны. **Перед использованием модели назначить их ShirtTemplate/PantsTemplate на полученные texture IDs.** Сам по себе импорт RBXMX не может показать локальный PNG как загруженную одежду. В текущем ConstructionService отдельного Images.builder нет, поэтому ID задаются прямо в шаблоне. Не оставлять пустую одежду при установке.
2. Импортировать BuilderNPC и отдельный Accessory BuilderHat в ServerStorage.Upgrades. Каску не вкладывать ещё и в NPC: dressBuilder добавляет её сам.
3. У NPC pivot намеренно центр HumanoidRootPart наY3, не основание. Ноги наY0, HipHeight2, HRPheight2: ConstructionService вычисляет StandHeight3 и ставит root над землёй. Не сдвигать pivot к ногам — иначе код поднимет строителя второй раз. Это специфика персонажа; строительные секции имеют базовый pivot отдельно.
4. HRP Anchored=true, остальные части держатся на суставах; код ConstructionService повторно выставляет те же свойства. Все части Massless и без коллизий/запросов/касания. InvisibleHRP намеренно пересекает туловище и не считается видимой геометрией.

## Проверки

VALIDATION.json создаётся независимым разбором финальных RBXMX:19частей NPC,16узлов тела с HRP,15Motor6D, связный граф отHRP, совпадение мировых bindframe каждого C0/C1, стандартные имена, нулевой низ ног и правильный StandHeight.153пары видимой геометрии без положительного объёмного пересечения; внутренний невидимый HRP исключён. Каска3детали без пересечений. PNG в точности совпадают с маской18панелей; размеры и SHA-256 проверены.

builder_preview.png512×512 показывает реальную одежду и каску на каноническом блочном манекене. Это локальный рендер, не Studio-скриншот. Классическую одежду на фактическом R15, масштаб тела, ориентации Attachment, движение и тени окончательно проверить в Studio.

Обязательный тест: импорт, назначенные Shirt/Pants, создание4строителей, ноги на земле, walk/run/hammer/carry с правильными плечами/локтём/бёдрами, каска, молоток/доска от кода, отсутствие дублей, телефон и режим «Меньше эффектов». Здесь нет загрузки/модерации одежды и runtime-теста. Пачка не меняет игровой код/цены/ID.

## Воспроизведение

Python3+Pillow+NumPy;node+@resvg/resvg-js;Rojo.

    python3 source/build_builder.py
    node source/rasterize.cjs
    python3 source/render_builder.py
    python3 source/validate_builder.py

Всё создано кодом из собственных простых форм; ImageGen не использовался. UV_MAP.json и source-svg/ сохраняют точное векторное оформление.
